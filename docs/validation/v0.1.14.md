# v0.1.14 部署后验收

## 结论与范围

2026-09-26（UTC+8），维护者替换本地交付的 Linux amd64 插件并重启 CPA 后，对真实已配置服务执行验收。目标模型显式固定为 `gpt-6-astra-basispoints`，思考等级 `xhigh`。最终有效验收包含 **15 次 HTTP 请求 + 3 次真实 Codex CLI 请求**，全部 HTTP 200，功能断言通过。

本次发布覆盖 #11 的中继封装问题、#4 的工具调用路径，以及 #12 的流式正文事件缺失；#6 已于先前版本关闭，本版继续减少其所述 custom 输入多层转义风险。#5 为独立图片请求体问题，不据此关闭。

## 真实接口检查

| 场景 | 请求数 | 检查结果 |
| --- | ---: | --- |
| 流式 pong、非流式 pong、中文多行正文 | 3 | 精确正文、换行和双空格保留；delta 与最终正文一致 |
| function 非流式及带命名空间的流式往返 | 4 | 引号、反斜杠和中文参数完全保留；新随机工具结果精确回传 |
| custom 最小补丁非流式往返 | 2 | 输入原文保留，真实写入隔离临时文件，回传文件 SHA-256 |
| custom 36 行密集引号补丁：流式、命名空间非流式、命名空间流式 | 6 | 三组实际补丁写入内容一致；工具输入 delta、done、最终输入一致，文件哈希精确回传 |
| Codex CLI 0.156.1 的实际 apply_patch → shell 读取 → 最终回复 | 3 | 实际文件内容及 shell 读回精确匹配，最终回复正确，退出码 0 |

CLI 捕获确认请求使用本插件模型，而非原生模型，并包含动态 `input[].additional_tools`。工具实际执行仅发生在本地一次性验证目录，未修改生产业务数据。

正文流检查覆盖 `output_item.added → content_part.added → output_text.delta → output_text.done → content_part.done → output_item.done → response.completed`，验证原始索引、item_id、连续 sequence_number 与完成状态。初始事件正文为空，避免重复拼接。custom 补丁按其语法允许结束标记后有或没有一个换行；补丁内所有字符及最终文件内容必须完全一致。

## 本地回归与构建边界

- 构建输入中的全部 Go 文件及模块文件与维护者已部署的 0.1.14 本地包源码清单一致；本轮验收没有修改运行代码。
- 纯源码快照通过 `go test -race -count=1 ./...`、`go vet ./...`、gofmt 和 `go mod tidy -diff`；既有 GitHub Actions 工作流通过 actionlint。
- 先前 54 项隔离 CPA/实际动态库检查验证了有界重生成、失败零交付及失败后凭据可用性；这些故障注入不是生产模型输出概率测量。

## 保留的异常与排除依据

1. 最初验证脚本把 JSON 放入 curl 配置字符串，导致中文 Unicode 转义在客户端被错误发送成字面量 uXXXX。本地收包自检确定损坏发生在测试客户端；改为发送原始 UTF-8 文件字节后，中文、emoji、引号、反斜杠和控制字符四组字节自检全部通过。原失败记录保留，不计入有效验收；插件源码未因此修改。
2. 验证期间全局默认模型发生外部切换，一组额外 CLI 测试使用了非插件模型，因此明确排除。后续显式固定 Basis Points 型号并重新执行完整矩阵；最终验收期间全局配置文件未变化。未修改或恢复使用者的全局配置。
3. 隔离 CLI 的扩展目录预热出现非致命 401/清单提示；不影响三次目标 API 请求、补丁执行、读回或退出码，不将其表述为插件认证失败。
