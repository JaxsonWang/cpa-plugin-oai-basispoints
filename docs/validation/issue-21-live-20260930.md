## 频繁错误的含义与处理范围

用户在本会话报告 `byte_offset=32/23/307`。这些诊断来自函数工具中继 `code` 的 JSON 解码，不是源码行号，不表示密钥失效，也不能据此断言是某一个固定字符。常见触发输入包含未正确编码的双引号、反斜杠或换行；本次未获得这些具体失败的原始上游参数，不能确定每次的实际字符。

- `stream disconnected before completion`：如果正文或摘要已交付，插件不能安全重放整轮；会保留已交付内容并以失败事件结束，不发送伪造的 `response.completed`。
- `unexpected status 422`：交付前工具校验最终失败，客户端收到真实 HTTP 422。缺少已经交付内容，并不意味着一次重生成一定能恢复。
- `buffered`：当前回合存在可调用工具时，所有内容等待整轮校验，复用既有最多一次重生成；第一次失败不输出，第二次成功只交付第二次结果。连续两次失败仍报错。

这是可靠性取舍，不是自动补引号或忽略坏参数。尤其对于 shell、patch 等工具，猜测修改参数可能改变操作含义，因此没有增加宽松解析、吞错、伪造工具结果或无限重试。

启用缓冲后，**带工具回合的正文和推理摘要不再实时显示**，即使最终没有调用工具。无工具或 `tool_choice: none` 仍实时交付。该取舍已在修改前向用户说明并得到批准；不能同时承诺工具回合始终低首字延迟和交付前整轮重生成。
