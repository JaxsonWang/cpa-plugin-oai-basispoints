# v0.2.7 发布验测

日期：2026-09-29（UTC+8）。本版只提交和发布插件仓库改动，不修改或替换 CPA 主程序，不自动部署、修改配置或重启 NAS。

## 变更与候选关系

- 将 JSON、SSE、WebSocket 的上游失败统一分类，并跨插件 ABI 保留安全的错误标识；已交付流通过 `error.status` 表达状态，不重放已提交请求。
- 已知错误码来自上游错误事件；429 和错误类型可能由插件按已知错误码映射，不一定是上游原始 HTTP 429。插件没有新增主动限流，也不会解除 Basis Points 上游的配额或速率限制。
- 用户此前替换并验测的 Linux AMD64 候选仍标记为 `0.2.6`，不是 GitHub 已发布的旧 `v0.2.6` 构建。正式版将版本号更新为 `0.2.7`，不改变该候选已经验测的实现逻辑。
- `AGENTS.md` 固定纯插件实施边界；当前 CPA 工作区干净，交付不包含宿主补丁。

## 已完成的联调及线上候选验证

- 未修改的 CPA 加载实际插件动态库，通过 7 项纯插件功能断言；开启宿主 `request-retry: 1` 的 4 项请求错误补验，上游仍分别仅执行一次。该验证使用隔离本机合成上游，不等于线上服务验收，详见 [纯插件上游失败分类验测](stream-failure-close.md)。
- 用户替换 Linux AMD64 候选后，真实 HTTP、SSE、function 工具及 WebSocket 同连接续接等 8 项检查通过，其中 6 次客户端生成请求均获得成功终态。验测器不自动重试，但未改变 CPA 既有内部重试配置，不据此断言上游只有六次尝试，详见 [线上候选验测](live-plugin-only-20260929.md)。
- 自然流量日志已观察到 `429 / rate_limit_exceeded / rate_limit_error`，证实新错误分类逻辑生效；未故意制造限流或进行压力测试。

## 仍然存在的边界

- 未修改 CPA 仍可能隐藏限流等非请求类错误并异常关闭下游 WebSocket。插件不控制该连接的 Close 帧，不宣称所有 `Connection reset without closing handshake` 已解决。
- 没有重放最初的长上下文故障会话，没有覆盖所有客户端 UI、图片组合或工具类型；未独立读取 NAS 动态库 SHA256。
- 新发布的 `0.2.7` 不会自动安装到 NAS。此前线上验收证明同逻辑候选行为，不冒充正式发行二进制已经部署后的验收。
