# v0.2.5 代理消息原生字段验测说明

日期：2026-09-29（UTC+8）。本版保留明文 `agent_message` 的上游原生结构，增加协议回归与验收记录；不修改 CPA 主程序、客户端全局配置或服务端凭据。

## 背景与修正边界

最初仅复现了 `author` / `recipient` 随历史输入透传，并未证明上游拒绝它们。随后未发布的本地测试包错误地移除了这两个字段，以独立正文标记替代来源信息。部署后实际收到 `Missing required parameter: 'input[29].author'.`，确认这一适配不符合上游契约。

该错误转换已完整撤回：保留原生 `author` / `recipient`、消息类型及原正文，不插入来源标记、不修改客户端原始历史，也不为本来就缺少字段的输入编造身份。`internal_chat_message_metadata_passthrough` 仍按原逻辑移除。

正式 `v0.2.4` 的生产逻辑原本已保留这两个字段；错误只出现在本轮未提交、未发布的本地测试包。`v0.2.5` 在恢复后的既有逻辑上增加注释、回归测试及文档，并递增版本号，不把未发布候选的问题描述成正式 `v0.2.4` 的缺陷。

代理 `encrypted_content` 仍在请求上游前明确拒绝，本版不宣称支持多代理 v2 密文协议。

## 本地验证

- 针对已报告错误构建严格的必填字段夹具：旧候选在有效原生消息上复现相同的 `input[29].author` 400；恢复字段后通过。本来就缺少 `author` 的负向输入仍收到上游错误，没有被补造字段或掩盖失败。
- 覆盖直接历史转换、HTTP 请求体及本地真实 WebSocket 帧，包含 Responses / Codex、流式 / 非流式组合；校验身份字段、正文及空白、重复转换、嵌套同名字段和原始输入不变。
- 733 项 Go 测试及子测试通过，启用 race；16 项源认证页面测试通过。
- `go vet ./...`、`go mod tidy -diff`、gofmt、actionlint、`git diff --check` 通过。
- 检查基于干净源码快照运行，避免工作区忽略的历史 `build/` 夹具进入 Go 包扫描；未删除这些历史证据或更改模块依赖。

本地模拟上游和回环 WebSocket 验证用于检查协议及传输路径，不等同于生产服务验收。

## 用户更新后的真实服务验收

用户确认更新修正后的 Linux `.so` 后，直接向当前配置的 CPA / Basis Points 服务发出请求，模型为 `gpt-6-astra-basispoints`，推理等级为 `xhigh`。输入只使用专门生成的测试文本与随机标记，不上传实际会话内容，不修改服务配置。

| 验证项 | 实际结果 |
| --- | --- |
| 普通请求基线 | HTTP 200，`completed`，精确返回预期文本 |
| 原生代理消息，非流式 | 保留 `author` / `recipient`，HTTP 200，准确读出仅位于代理消息正文的随机标记 |
| 原生代理消息，流式 | HTTP 200，准确返回相同标记，恰好一次 `response.completed`，无失败事件 |
| 完整历史续接 | 保留代理消息及上一轮输出，流式 HTTP 200，标记一致，成功终态完整 |
| 缺少 `author` 的负向对照 | HTTP 400，明确指出缺失 `input[29].author` |
| 负向对照后的普通请求 | HTTP 200，`completed`，准确返回预期文本 |

合计 6 次真实请求：5 次正常 200、1 次预期 400，无意外失败。请求前后客户端配置哈希一致。

负向对照的第一次结果汇总额外要求错误正文包含 `missing_required_parameter` 字样，但实际规范化响应仅保留 `Missing required parameter` 及精确字段位置。依据已保存的原始响应复核为符合预期的 HTTP 400；没有修改原始响应、重发网络请求或把实际失败当成成功。

## 发布与验测限制

- 真实服务验收针对内置版本仍为 `0.2.4` 的修正本地候选；`v0.2.5` 发布准备仅在相同请求逻辑上递增版本，并补充注释、测试和文档。不能将前述结果描述为已安装正式 `v0.2.5` 的远端验收。
- 没有独立读取服务器上的动态库 SHA-256，未据此声明远端二进制与本地逐字一致。服务验收使用客户端 HTTP JSON/SSE，未独立核实服务内部最终选择的 HTTP 或 WebSocket 上游传输。
- 正式包由既有 GitHub Actions 从 `v0.2.5` 标签构建，覆盖 macOS、Linux、Windows 的 AMD64 / ARM64，资产和摘要以 GitHub Release 为准。
- 发布不会自动替换现有部署。安装新动态库后需重启 CPA，并确认版本为 `0.2.5`。
