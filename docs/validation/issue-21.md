# #21 流式工具回合校验与重生成

日期：2026-09-30（UTC+8）。本次为本地未发布修复，不修改或替换 CPA 主程序，不改动现有服务配置或部署。

用户随后更新 `.so` 并授权启用缓冲配置后的结果见 [线上专项及历史回归](issue-21-live-20260930.md)。后续配置变更和未通过的摘要覆盖项不改写本次本地验测边界。

## 复现结论

- 基线为插件 `v0.2.8`，提交 `280e28b`，开始时工作区干净。虽然问题报告使用 `v0.2.7`，当前本地版本仍存在同一交付边界。
- 用本机合成上游先发送中文正文或推理摘要增量，再返回含漏转义 `code` 的工具调用。修复前新增的 8 个恢复/耗尽场景全部失败，均观察到 `attempts=1`、`upstream_closes=1`、`early_delivery=true`，无法进行交付前重生成。
- 原因是 `streamDelivery.consume` 在首个有效增量处提交下游，终态工具校验晚于此时。`readStreamingResponse` 正确禁止对已提交响应重生成，但没有保留实时模式以外的选择。
- 未修改 CPA 的实际 HTTP/SSE 联调也复现了这一行为：已交付正文、HTTP 200、一个流内 `error`，其中 `status=422`、`code=invalid_tool_call`；没有工具和成功终态。不能将其描述成已经发送的 HTTP 200 被改成 HTTP 422。

现有增量模式已经保留正文并发送协议错误。它不是“某个工具已执行失败”的结果项；插件不会执行客户端工具，也不能伪造调用结果或保证客户端自动续跑。因此本次选择提供交付前的安全缓冲，而非捏造局部工具执行结果。

## 本地修复

在现有 `plugins.configs.oai-basispoints` 配置下合并一个字段：

```yaml
stream_tool_mode: buffered
```

- 默认 `incremental` 不变，继续实时交付正文及推理摘要，避免默认回退 #18 的实时摘要能力。
- `buffered` 只作用于本轮存在可调用客户端工具的流式请求，复用工具目录和 `tool_choice` 判定，支持命名空间、动态工具及 `OriginalRequest`；无工具或 `tool_choice: none` 不缓冲。
- 缓冲期间使用原有消息/摘要状态机校验事件和终态一致性，不提交下游。工具整批校验失败时，丢弃整轮未交付内容，使用既有一次重生成。第二次成功只交付第二次响应；两次失败仍返回真实 422，没有坏参数、半批工具或失败尝试正文泄漏。
- 不增加重生成次数，不猜测修补 JSON，不降低 schema 校验，不新增传输回退。上游失败、断流、截断、超时和大小超限不因缓冲而重生成；取消与插件停用仍关闭上游。
- HTTP/SSE 与上游 WebSocket 共用该模式，非流式路径不变。配置纳入现有 YAML/JSON 持久化、状态输出及配置字段注册；非法枚举明确拒绝。

**代价：所有可调用工具的回合都必须等待完整响应，包括最终仅返回正文的回合。** 首字和摘要可能等待整轮完成及一次重生成。上游仍是流式，最终用量保留上游成功响应的原值，不杜撰失败尝试的聚合用量。该功能改善可恢复性，不保证模型永不漏转义。

如果 `data_dir` 非空，已有 `settings.json` 中的同名字段继续覆盖 YAML；示例配置使用空 `data_dir` 时只由 YAML 管理。此次没有修改用户现有配置，也没有自动启用缓冲。
