## 发布流程

- 版本号递增为 `0.2.4`，使用既有 GitHub Actions 从 `v0.2.4` 标签构建 macOS/Linux/Windows 的 AMD64、ARM64 六平台发行包。
- 发布门禁先执行源码测试、静态检查和版本标签一致性检查；所有平台构建完成后才上传 Release 资产及 `checksums.txt`。
- 正式发行包的 SHA-256 以 Release 内的 `checksums.txt` 为准，不用本地 Zig 交叉编译产物摘要替代 manylinux2014 构建结果。
- 发布本身不代表服务已经升级为 `0.2.4`；用户仍需安装对应动态库、重启 CPA 并核对实际版本。

## 验证边界

- 原始 issue #15 的 Windows 长对话与失败请求仍未提供；当前九图颜色与历史回放测试不是该私有会话的逐字复现。
- 图片签名识别不等于完整解码；不承诺本地发现所有合法头但内容损坏的图像。
- 未启用多代理 v2、JSON Schema 输出、Fast、独立 compact 或 ID 续接；明确拒绝是原有边界，不是新增功能。
- 不改变已加载的服务器动态库，也不自动重启服务。正式六平台资产使用 Actions 从标签构建，其摘要与本地交叉编译候选可能不同。
