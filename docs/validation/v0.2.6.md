# v0.2.6 推理摘要交付与历史回归验测

日期：2026-09-29（UTC+8）。本版修复 #18 的摘要过滤问题，不修改 CPA 主程序、客户端全局配置、认证或上游超时设置。

## 修复范围

- 流式交付接受 `reasoning` 类型的 `response.output_item.added/done`，以及 `response.reasoning_summary_part.added/done`、`response.reasoning_summary_text.delta/done`。
- 首条非空摘要或正文增量触发交付，先发送响应元数据及积压的合法事件；只有条目生命周期、没有非空增量时，不提前提交。
- 推理条目使用独立状态，不经过普通消息登记；条目原样保留，不将密文转成正文。校验摘要与终态一致，并在回放终态时补齐未交付部分、抑制重复。
- 工具仍须完整终态整批验证；任何摘要或正文已经交付后，失败以协议错误结束，不再重生成、不交付半批工具、不伪造成功。

主要代码：`internal/basispoints/stream_events.go`、`protocol.go`；新增 `reasoning_stream_test.go`，并扩展既有消息、失败、断连及停用测试。

## 验测器复核说明

保留初始脚本结果及原始响应，没有重写记录掩盖失败：

- `compact-stream` 的 400 来自 CPA 提前拒绝流式 compact，而非预期的插件错误文案；依然符合“不冒充压缩成功”的边界。
- 两个 Claude 用例最初沿用历史关闭评论中的预期 400；实际收到完整 Anthropic Message/SSE、OK 正文和 end_turn，随后真实 Claude Code 也成功，因此不属于旧 500/503 故障复现。
- 初始时序脚本误要求 `[DONE]`。本项目既有 codex 传输明确省略该哨兵；完成以 `response.completed` 为准。后续仍严格要求唯一成功终态、无错误、连续序号及内容一致。纯文本 high 没有摘要这一独立结果保持未通过摘要断言。

## 发布与部署边界

- 上述真实服务验收对应内部版本仍为 `0.2.5` 的本地修复候选；`v0.2.6` 发布准备只在同一行为逻辑上递增版本号并补充文档，不将候选验测描述成正式发行包的远端验收。
- 没有独立读取服务器动态库 SHA256；客户端到 CPA 的 HTTP/SSE 实测不证明服务器内部具体选择了哪条上游传输。
- 正式六平台包由既有 GitHub Actions 从发布标签构建，不能混用 Linux AMD64 与 ARM64 产物。安装新动态库后需要重启 CPA。
- 发布不会自动替换、重启现有服务，也不修改用户凭据、客户端全局配置或历史 issue 的已有关闭状态。
