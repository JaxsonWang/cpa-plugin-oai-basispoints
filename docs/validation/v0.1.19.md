# v0.1.19 上游 WS 优先及安全回退验测

> 后续记录：用户于 2026-09-27 确认替换后，管理页面已核实加载 0.1.19；定向业务检查通过，但线上 WS 握手出现 404 后回退 HTTP，不能视作线上 WS 成功。详细现场结果及新增凭据开关门槛见 `v0.1.20.md`。下文保留最初候选构建时的原始验证边界。

## 结论和范围

2026-09-27（UTC+8），在 v0.1.18 基础上增加 **CPA 插件 → Basis Points** 的 WS 传输，并生成本地 Linux amd64 候选。客户端到 CPA 使用 HTTP/SSE 还是 WS，不决定本插件到上游使用哪种传输，两段链路应分别判断。

真实 Basis Points 已用用户授权的本机 OAuth 凭据完成 `101` 升级、有效握手响应、Ping/Pong 及 `response.create` 推理；不是根据公开 Responses 文档或未经鉴权的 `401` 猜测支持情况。正式插件使用与原 HTTP 通道一致的鉴权配置；凭据只从原有文件读取进入内存，不写入测试脚本、报告或新增配置。

本次只修改插件，不修改 CPA 主程序、用户个人客户端配置或运行中的远端部署，**没有提交、推送或发布 GitHub 版本**。本机实际运行的是同源码 macOS 动态库，Linux 文件尚待用户替换验收。

## 回退规则

| 阶段或结果 | 行为 |
| --- | --- |
| `upstream_transport: auto` | 每轮生成先尝试 **1 次** WS 握手；默认上限 **5 秒**，可配置 1～30 秒，不连续重试握手 |
| DNS/连接/TLS/Upgrade 失败、握手超时、404/405/426/5xx 等拒绝升级 | 尚未提交生成，调用 **1 次**宿主原 HTTP 通道；流式请求为 SSE，非流式保持 HTTP JSON/SSE 解析语义 |
| 握手返回 401/403/407/429 | 保留鉴权、代理鉴权或限流失败，不换通道掩盖问题 |
| 已建立有效 WS 连接 | 此轮不再切换 HTTP；即使发送报错或尚未收到正文，也不假设上游没有处理请求 |
| WS 数据帧报告应用错误 | 保留可识别的 HTTP 等价状态，特别是参数 400/422，避免泛化成 502；不回退、不重放 |
| 发送后断线、超时、非法事件、非文本消息、尺寸越界 | 明确报错；已发送正文保留，但不产生成功终态或半批工具 |
| 客户端取消、总体截止时间已到、插件 quiesce/shutdown | 关闭正在握手或读取的连接并结束；不启动 HTTP 回退 |
| 下一独立请求 | 重新优先尝试一次 WS；不记全局失败次数、不跨账号冷却、不做探活后台任务 |
| `upstream_transport: http` | 不握手，直接使用旧 HTTP/SSE 实现 |

选择一次而非三次握手，是为了避免不可用 WS 在每轮生成前串行增加最多 15 秒等待。5 秒是本地配置默认值，不代表上游首字保证。成功 WS 仍需等待上游推理；本版不引入跨请求连接池，不声称 WS 必定比 SSE 更快。

原有**工具格式修正**保持不变：在尚未向客户端提交正文/工具时，畸形工具最多允许一次额外生成；如果需要重新生成，该轮也遵守上述一次握手规则。这是原有生成校验机制，**不是握手重试**，可能增加上游用量。已交付正文后不进行同请求重生成。

CPA 自己的凭据调度、客户端自行重新请求不属于插件本次尝试；不能把插件“不重放”理解成整套系统永远只发一次请求。Claude Code 的独立非流式回退边界继续保留，见下文。

## 配置和实现

在现有 `plugins.configs.oai-basispoints` 配置中可设置：

```yaml
upstream_transport: auto
ws_handshake_timeout_seconds: 5
```

两项省略时即使用上述默认值；需要禁用 WS 时只改 `upstream_transport: http`。仍沿用原配置优先级：存在持久化 `settings.json` 时，其中已有字段覆盖 YAML；`data_dir: ""` 表示不使用该持久化目录。本版没有改写用户现有配置。

- `websocket.go`：根据现有 `responses_url` 将 HTTP(S) 协议转换为 WS(S)，复用已准备请求，只移除 WS 不接受的 `stream`/`background` 并加入 `type: response.create`。每轮生成独立连接，保持完整历史输入，不新增 `previous_response_id` 能力。
- WS 事件进入与 HTTP/SSE 相同的正文交付及终态解析逻辑；工具仍完整缓冲并整批校验，保留原文、目录、call ID、schema、并行约束和历史往返。
- `request_lifecycle.go` 接入原版 CPA 的认证后拦截器与请求完成通知，只关联本插件模型请求，不拒绝 Claude、不改正文；`runningStream` 在握手开始就绑定原始连接，取消无需等到收到第一字或等满握手上限。
- `auth.go` 把全局或凭据代理传入虚拟认证属性，刷新时保留/更新/清除相应属性。显式凭据代理优先，`direct`/`none` 表示直连，否则继承全局代理或环境代理。
- WS 支持 HTTP CONNECT、SOCKS5/SOCKS5H；后者由代理解析目标域名。不支持的代理类型（如 HTTPS 代理）直接使用宿主 HTTP，不先尝试绕过代理发送 OAuth。
- 插件 ABI 不序列化宿主任意内存 `HTTPClient/RoundTripper` 或执行期自定义传输实现；依赖这些定制能力的部署应使用 `http`。本次证明的是配置级代理继承，不宣称复制全部宿主网络策略。
- 回退日志只记录原因、状态和握手次数；断线错误可含标准关闭码，不回显上游关闭原因正文或凭据。

旧测试的 HTTP 夹具显式选用 `http`，保留原有断言；新的 WS 夹具覆盖新默认路径，两组原版宿主测试覆盖同一主功能集合。关闭问题对应的工具原文、命名空间、schema、参数 400/422、非流式 JSON/SSE、增量生命周期、图片及上下文边界继续纳入回归。本次没有变更 issue 状态，也不据此保证所有未知输入都没有问题。

原版宿主/CLI 回归使用**合成推理上游**；真实的是原版 CPA、ABI、代理、取消和客户端文件/工具行为。Codex `0.158.0-alpha.2` 与 Claude Code `2.1.247` 均识别坏工具/截断错误，不将 HTTP 200 误判为成功，不执行异常工具。

Claude 仍可能在流式错误后独立发一个非流式请求：坏工具夹具合计三次上游生成，截断夹具两次。这与 v0.1.18 一致，插件没有对已提交的单个流做 WS→HTTP 重放，不新增跨请求缓存阻断客户端行为。

### 真实 Basis Points

直接用本地动态库调用真实上游，测试中的宿主 HTTP 回调被设置为失败，确保成功结果确实来自 WS：

1. 非流式正文及流式正文成功，流式 delta 与终态一致。
2. function 调用及结果往返成功，保留引号、反斜杠及中文参数。
3. custom `apply_patch` 调用及结果往返成功，校验原始补丁内容及实际测试回传标记；该项验证传输原文，不冒充生产文件写入。文件增删改另由原生 Codex 夹具验证。

初始真实测试在自定义工具调用中遇到一次上游中断，返回 `502 upstream_ws_interrupted`，HTTP 回调次数为零，未重放。保留失败日志；诊断中继和再次直连均成功，随后完整六项真实请求通过。**没有证据确认该次中断的上游根因，也没有加入未经证实的分帧补丁或宣称从此不会断流。**

本次为有限真实样本，不是吞吐基准或长期稳定性测试；不拿与 SSE 不同时段的采样宣称速度提升。
