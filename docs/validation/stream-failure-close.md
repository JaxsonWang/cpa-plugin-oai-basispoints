# 纯插件上游失败分类验测

日期：2026-09-29（UTC+8）。这是本地未发布修复记录，不代表 NAS 已安装新版本。实施边界以项目 `AGENTS.md` 为准：不修改 CPA 主程序，必须兼容未修改的宿主。

用户随后替换 Linux AMD64 候选后的线上结果另见 [纯插件修复候选线上验测](live-plugin-only-20260929.md)，不混同本地夹具结果与真实上游验收。

## 修复范围

- 插件在 JSON 响应、缓冲 SSE、增量 SSE、上游 WebSocket 中统一处理 `error`、`response.failed` 和 `response.cancelled`。
- 明确的 400–599 状态优先；缺少状态时，只根据已知协议错误标识推断请求、认证、权限、限流或服务端失败。未知错误仍返回上游失败，不推测其原因。
- 保留安全的 `code`、`type` 和事件名称；不回显上游任意错误正文、请求参数、凭据或图片。未知分类字符串也不直接回显。
- 插件 ABI 错误正文保留结构化分类，避免请求类错误在进入 CPA 时丢失语义。已经提交的流式 HTTP 响应不改写 HTTP 状态，改为在 `error` 事件中携带 `status`。
- 不重放已开始交付的请求，不泄漏部分工具批次，不发送虚假的 `response.completed`。

## 宿主边界与范围更正

- 上轮越界修改的 CPA 关闭实现、既有测试和新增关闭测试已全部撤销，`CLIProxyAPI` 工作区恢复干净。
- 插件错误分类、脱敏诊断及流内状态透传可以独立生效，不要求更新 CPA。此前“必须同时更新插件和 CPA”的交付结论不适用于这些插件修复。
- 插件没有直接操作 CPA 与客户端之间 WebSocket 控制帧的接口。未修改宿主仍可能隐藏服务端错误并直接断开连接；不能将错误分类优化描述成关闭握手已经修复，也不能为绕过宿主而将真实 5xx 伪装成参数错误。

## 验证结果

新增回归先确认插件原实现会丢失请求错误状态，修复后插件完整检查通过。撤销宿主修改后，再使用干净 CPA 源码构建的程序验证纯插件兼容性；关闭码 1006 明确记录为未解决的宿主行为，而不是已修复的验收项。

插件完整检查使用逐文件 SHA256 核验的干净源码副本，避免忽略目录 `build/` 中历史诊断 Go 文件参与包扫描；没有删除历史文件或排除正式测试。

### 未修改宿主上的纯插件联调

使用已经通过完整检查且源码 SHA256 仍一致的插件动态库，以及从干净 CPA 源码重新构建的服务程序。临时 HOME、认证目录和合成凭据均位于独立目录。业务请求仅发送到本机回环合成上游，没有使用真实账号或上传原会话。

1. 非流式 JSON 请求错误：真实 HTTP 400，保留 `context_length_exceeded`。
2. 已交付正文的 SSE 请求错误：外层 HTTP 200，流内错误分类保留。
3. 尚未交付正文的 WebSocket 请求错误：客户端收到明确的 `context_length_exceeded` 错误事件；之后宿主仍以 1006 关闭。
4. 已交付正文的 WebSocket 请求错误：保留正文及明确错误事件；之后宿主仍以 1006 关闭。
5. 尚未交付正文的上游服务错误：不泄漏内部正文，仍观察到宿主的 1006 关闭。
6. 已交付正文的上游服务错误：保留已交付正文，仍观察到宿主的 1006 关闭。
7. 已交付正文的限流：插件保持限流分类；宿主对客户端仍隐藏该错误并以 1006 关闭。

七项均确认上游只收到一次请求，没有伪造成功终态或泄漏夹具中的私有错误正文。插件直接上游 WebSocket 的流式/非流式、交付前后失败另由真实 socket 回归覆盖。

上述七项基线夹具设置 `request-retry: 0`，用于隔离插件行为。另将四项请求错误场景改为 `request-retry: 1` 后补验，仍分别只有一次上游调用。这证明已分类的请求错误不会仅因宿主允许重试而被当作普通 502 重跑；不代表真实 5xx、限流或客户端自主重连已经被消除。

此前修改过宿主的联合测试记录仅作为已撤回方案的历史证据，不用于证明纯插件兼容性。纯插件验测保留错误分类、正文、单次上游调用及隐私断言；关闭帧限制单独报告，不冒充已修复。
