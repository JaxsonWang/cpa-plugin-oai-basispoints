## 发布范围

- 默认使用 host 凭据模式，由 CPA 原生加载、刷新并持久化 Codex OAuth 文件；执行时读取当前凭据。保留显式 virtual 及现有持久化覆盖规则，不强制迁移已有配置或修复已失效的 token。

- 增加可选 buffered 工具回合交付，默认 incremental 不变；仅复用既有一次重生成，不修补错误参数、不交付半批工具。
- 移除独立设置页，WS 开关统一使用 CPA 凭证设置；配置说明统一为简体中文。
- 增强 WS 断流的脱敏进度诊断，并通过已有 host.log 回调记录 warning，保证 self 路由绕过原生日志路径时仍有诊断记录。

### 发布前保留的失败与修复

首次发布预检中，全量 955 项测试、10 项 host 和 8 项缓冲联调通过，但 WS 诊断原生夹具在 `ws_interrupted` 场景失败：默认 host 的 self 路由没有经过原生账号错误日志，而原版 CPA 下游 WS 又隐藏了 5xx 事件，导致日志中没有诊断字段。

没有删掉日志断言或修改宿主。插件在原断流位置复用 `host.log` 回调，记录同一条脱敏 warning，并传入当前 `host_callback_id`。新增检查覆盖日志只调用一次、上下文不丢失、日志内容与实际错误一致，以及日志回调失败后仍返回原断流错误；不回显上游文本、关闭原因或凭据。

修复后原有 4 项原生夹具全部通过：HTTP 非流式、已交付 SSE、下游 WS 交付前/后断流。每个场景均只有一次上游请求，无 HTTP 重放和虚假成功终态。下游 WS 的关闭码仍可能为 1006，由宿主控制，未标记为已修复。

本地证据目录为 `build/release-v0.2.9-20260930-fOkN9g/`：初始 `source/`、`tests.jsonl`、`diagnostic-cases/` 保留失败现场；最终 `source-final/`、`tests-final.jsonl`、`diagnostic-acceptance-fixed.jsonl`、`host-acceptance-final.txt` 和 `buffered-acceptance-final.jsonl` 记录发布源码复验。

## 验证边界与升级注意

- 没有独立读取远端候选 so 的 SHA256，没有强制真实 OAuth 刷新或等待完整自动轮换周期。
- 下游 WS 请求成功不等于独立确认 auto 选择了上游 WS；没有制造真实网络断线、重放原始长会话或验证报告者的 Windows GUI。
- host 不自动继承 CPA 原生账号级优先级、冷却、用量归属及 host.http 请求日志捕获；本次只补充安全的断流诊断日志。
- buffered 牺牲所有工具可用回合的首字与摘要实时性。持续无效工具参数仍会失败，不承诺消除 422 或恢复被宿主/客户端另行重试的请求。
- 已保存的 virtual 仍会覆盖新默认值；需要 host 时应显式修改对应配置。安装正式版动态库后需重启 CPA，本次发布不自动部署。
