旧提示词始终输出两个硬编码示例：`exec_command` 函数和 `apply_patch` 原始文本工具，未考虑实际可调用目录、命名空间、动态工具覆盖、`tool_choice` 和参数 schema。因此，目录将 `apply_patch` 声明为函数时，提示词仍教模型直接发送补丁，生产解析路径确实返回 `code invalid_json`；只有命名空间工具或强制指定工具时，也会教模型调用目录外或本轮禁用的工具。

修复内容：

1. 示例改用当前可调用目录中的 shell/patch 工具和完整名称，函数示例按已声明 schema 校验；不匹配或没有适用工具时不生成该示例。
2. 函数包装的补丁使用 `{"patch": "..."}` 参数对象，custom 补丁仍保留原始文本。
3. 协议说明、回合提醒及原有重生成提示都明确区分“函数参数对象先 JSON 序列化，再作为外层 code 字符串序列化”这两层编码，强调单个字符串参数也不能省略对象包装。

本次不改解析器、重试次数或错误类别；不猜测补引号、不反转义坏参数、不执行坏调用、不吞错误、不交付半批工具。它消除了一个明确的提示词误导来源，但不保证模型永不生成非法 JSON。
