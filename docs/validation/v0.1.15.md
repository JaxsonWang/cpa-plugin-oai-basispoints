# v0.1.15 本地验测包

此文保留最初本地验测记录，后续部署结果及候选修正见 [v0.1.16](v0.1.16.md) 与 [v0.1.17](v0.1.17.md)。v0.1.15 未单独发布。

## 修复范围

2026-09-26（UTC+8），修复 Basis Points 模型在 Codex 中缺少原生补丁工具的问题。CPA 会删除通用或非原生模型的 `apply_patch_tool_type`；此前插件只恢复上下文容量，客户端因此没有获得 `apply_patch`。

本版仅对本插件配置的别名同步其规范模型的补丁能力。保留 `null` 和字段缺失语义，遵循各自模型映射及凭据前缀，不强制所有模型开启补丁，不修改其他提供商或既有工具中继，也不恢复 Fast 等未支持能力。版本号为 `0.1.15`，本次只交付本地 Linux amd64 验测包，未发布或部署。

## 内部验证

- 新增回归先在旧实现上失败，修复后通过：缺失／null／freeform 的九组组合、多个模型、凭据前缀、其他模型不变及幂等性。
- 当前源码快照通过 `go test -race -count=1 ./...`、`go vet ./...`、`go mod tidy -diff`、gofmt、actionlint 和 `git diff --check`。
- 原工作区的 `go test ./...` 会扫描被忽略的历史 `build/` 残留测试并编译失败；未修改或删除这些残留。完整检查使用当前受版本控制文件的干净副本，包含本次所有 Go 修改，不排除任何正式源码或测试包。
- 加载同源码编译的 macOS arm64 动态库，实际调用插件 C ABI，确认版本为 `0.1.15`，模型目录将插件别名的补丁字段从 `null` 修复为 `freeform`，规范模型保持不变。
- 使用 Codex CLI/app-server `0.156.1`、隔离 `CODEX_HOME`、临时 Git 仓库及本地模拟上游，运行实际中继：`run_officejs → custom apply_patch → 工具结果回传 → 最终回复`。没有使用真实 OAuth 凭据或外部上游服务。
- 客户端实际完成一个文件修改、一个文件新增、一个文件删除；核对落盘内容，收到一个已完成的 `fileChange`（三个文件）及三次 `turn/diff/updated`，最终聚合 diff 包含三个文件和准确的修改前后内容。

## 部署验测与边界

1. 备份正在使用的旧动态库，替换为本次 `oai-basispoints.so`，重启 CPA，确认加载版本为 `0.1.15`。不要通过增加同目录副本加载第二个同 ID 插件。
2. 刷新或重启 Codex，使模型目录不再使用旧缓存；核对所选插件模型的 `apply_patch_tool_type` 为 `freeform`（以对应规范模型声明为准）。
3. 在新的测试会话中要求修改一个测试文件，检查原生补丁调用和会话内文件差异入口。仅通过 shell 写入的改动不保证产生原生补丁事件。
4. 此次未直接在 Linux CPA 进程中加载交付 `.so`，也未完成部署后的真实上游和桌面 UI 验收；这些由部署验测确认。历史会话缺失的结构化事件不在此次修复中补写。
5. 若验测失败，恢复备份动态库并重启 CPA；本次不涉及配置格式变更或持久化数据迁移。
