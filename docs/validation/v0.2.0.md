## 自动发布流程

现有 GitHub Actions `Release` 工作流先核对标签与源码版本并运行检查，再构建六个平台：

- macOS：amd64、arm64。
- Linux：amd64、arm64，使用 manylinux2014 构建环境。
- Windows：amd64、arm64。

工作流校验动态库导出和压缩包内容，全部构建成功后发布压缩包及 `checksums.txt`。各平台构建检查不等同于在每种系统、宿主版本和网络环境下完成实际运行验收。

## 升级核对

1. 下载对应操作系统和架构的压缩包，并核对 `checksums.txt`。
2. 备份旧库，替换当前插件文件；避免在扫描目录中保留多个相同插件 ID 的动态库。
3. 重启 CPA，在管理页确认实际注册版本为 `0.2.0`。文件名可以沿用原部署名称，不以文件名判断版本。
4. 配置可继续使用 `upstream_transport: auto` 或 `http`；凭据的 `websockets` 开关继续生效。旧配置里残留的 `http_only_auth_ids` 不再参与传输选择。
