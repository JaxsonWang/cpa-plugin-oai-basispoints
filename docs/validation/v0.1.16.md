# v0.1.16 能力修复、部署验测与发布阻断

本文保留失败候选的历史证据；修正后的部署复验结果见 [v0.1.17 验收报告](v0.1.17.md)。v0.1.16 未单独发布。

## 范围与结论

2026-09-26（UTC+8），在保留本地 v0.1.15 补丁修复的基础上完成以下修改：

- 按模型映射及凭据前缀同步 `multi_agent_version`、`multi_agent_reasoning_effort`。
- 从对应规范模型的实验工具列表中仅选取已验证的 `clock`、`send_user_message_async`；不自动启用未来未知工具，不改变 Code Mode、Node REPL 审核配置或其他提供商。
- `text.format` 为 `json_object` / `json_schema` 时，在调用上游之前返回 `400 unsupported_text_format`；格式结构非法时返回明确的参数错误。缺省、null、普通文本格式和既有 Codex 默认请求保持原行为。
- 不改动工具中继封装、历史身份回放、有界重生成、消息流回放、图片上传、OAuth 解析或宿主 Claude 转换代码。

上述内容记录 v0.1.16 候选的原始修改。用户随后报告已替换 `.so`；2026-09-26 部署后验测发现多代理 v2 的真实密文消息契约未实现。因此 v0.1.16 未通过发布门禁，未提交、推送或发布。不能将下述本地合成上游测试理解为完整生产验收。

## 部署后真实验测与阻断原因

2026-09-26 19:54—20:04（UTC+8），使用现有 CPA/Basis Points 服务、隔离客户端配置及真实推理响应验测。记录代理只替换隔离测试凭据并转发请求，不重写正常验收请求的模型、工具或正文。

- 23 项主用例通过：实时模型目录、正文流式/非流式、中文及空白、function/custom 工具、命名空间、引号密集补丁原文、工具结果回传、双图片和旧客户端默认请求。JSON 格式、Fast、compact、ID 续接的十项负例均按预期返回 400。
- 桌面内置 Codex `0.158.0-alpha.2` 使用服务实时目录，完成真实 `apply_patch` 写入、shell 读回及 `file_change` 事件；三次请求均为 200，文件逐字一致。
- Claude Code `2.1.247` 文本与真实 Bash 往返通过，三次 Messages 请求均为 200；个人 Codex 与 Claude 配置未修改。
- 时钟、休眠和异步提问真实执行成功，测试程序实际提交的异步答案进入父代理上下文。但子代理任务两次返回 502；这十次请求中八次为 200、两次为 502，整体能力验收失败。父代理正确报告未收到子代理答案，没有输出成功标记。
- 差分诊断：普通 `low` 请求为 200；原始子代理请求改成 `xhigh` 仍为 502；仅将已知测试明文从 `encrypted_content` 改为 `input_text`，保留 `agent_message` 类型，即返回 200 和正确任务答案。这是定位实验，不是生产修复或自动降级。

固定客户端版本源码证据：`rust-v0.158.0-alpha.2` 的 `codex-rs/core/src/tools/handlers/multi_agents_v2.rs` 中，模型工具来源的消息经 `agent_message_from_tool` 被当成 `AgentMessage::Encrypted`；`multi_agents_spec.rs` 对消息参数标注 `with_encrypted()`。本插件的中继生成普通字符串，没有实现原生消息密文契约，不能仅同步 `multi_agent_version=v2` 就声明支持。真实上游因此返回失败事件，插件按既有严格错误路径报告 502。

处置：保留失败记录，停止发布；在 v0.1.17 候选撤回未实现的多代理声明，对旧缓存/显式 v2 会话中的密文代理输入提前明确返回 400，不猜测解密，不把密文强转正文。补丁、时钟及异步提问继续保留。v0.1.17 需重新替换动态库并验测后才满足发布条件。

测试夹具也有两次启动准备问题：一次复用脚本边界不正确，实际运行了旧 Codex 补丁测试；一次隔离 `CODEX_HOME` 目录未创建，客户端未发送请求即退出。均保留记录并修正，不计为能力验收通过或生产故障。它们与随后真实 v2 请求的 502 是不同问题。

## 明确保留的未完成项

`text.verbosity` 的上游映射及能力声明尚未修复。旧版真实 Codex 请求默认包含 `text.verbosity=low`；直接改成拒绝或未经验证地透传会影响普通对话和工具链。

本地没有可用于直接核验 Basis Points 的 OAuth 凭据；现有代理会丢弃此字段，不能通过该代理的 HTTP 200 证明上游接受它。公开前端入口读取也未成功。因此本版保持既有行为，并明确记录该缺口，不假称参数已生效，也不以提示词替代原生参数。

原生 `web_search` / `tool_search`、Code Mode、Fast、Responses Lite 和运行中思考等级更新不在本版新增范围。严格结构化输出的修复是明确拒绝尚未实现的契约，不是新增 JSON Schema 生成功能。

## 验证记录

- 干净的当前源码副本通过 `go test -race -count=1 -json ./...`，记录 372 个测试/子测试通过、零失败；没有排除任何正式包。
- `go vet ./...`、`go mod tidy -diff`、gofmt、actionlint、`git diff --check` 均通过。使用源码副本是为了避开工作区原有 `build/` 内的历史残留测试，未删除或修改这些残留。
- 原版 CPA v7.3.17 实际加载同源码 macOS arm64 动态库，72 项 HTTP/CLI 检查通过。推理上游明确使用本地合成夹具，不是生产 Basis Points。
- Codex 桌面内置运行时 `0.158.0-alpha.2` 配合合成上游，注册并执行时钟、异步提问、多代理 v2；11 个父工具结果完成往返。测试程序实际提交夹具答案；子代理追加任务和消息均运行，`interrupt_agent` 返回先前状态 `running`。但该夹具直接生成子代理答案，未验证真实上游对代理密文内容的接受性；部署后的失败已否定据此宣称 v2 端到端可用的结论。
- 原生 `apply_patch` 对临时仓库完成新增、修改、删除，得到一个完成的 `fileChange`（三个文件）和三次 `turn/diff/updated`，最终聚合 diff 内容准确。
- 新格式检查覆盖流式/非流式、CPA 规范化输入、拒绝前零上游调用、错误信息不泄露 Schema，以及格式错误后同一凭据仍能处理正常请求。

初次客户端能力夹具未按实际运行时处理异步提问和追加任务消息：异步提问是带 questions 的异步 agentMessage，追加任务可通过开发者消息传入，而非同步提问 RPC/普通 user 消息。修正夹具并显式固定测试模型后重新验证；失败记录保留，不计为通过。没有因此修改生产执行逻辑或降低验收标准。
